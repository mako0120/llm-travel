# ローカル旅行条件 UI

Issue: #50。外部 AI API を使わず、条件整理から JSON 保存までをブラウザー内で完結させる。

## デザイン

- 白背景、文字 #183d3a、主要操作 #245c4f、下書き背景 #f2f6f3、罫線 #d4dfdc。
- 見出しは日本語明朝、フォームは OS の日本語ゴシック。外部フォント・画像を読み込まない。
- デスクトップは入力約 2 : 下書き 1 の2カラム。760px以下は入力、下書きの順に1カラム。
- 9条件を2列で入力し、右側に対応する9行を表示。モバイルは入力も1列。
- 操作は入力 → 確認 → 条件ファイル保存。確認後の編集は入力を保持する。
- 初期コンセプトの全項目入力形式を採用。架空の会話履歴は置かず、下部は使い方の開閉欄。CTA は実際の操作に合わせ「入力内容を確認する」。

## 実行とデータ境界

`python -m travel.webapp` でローカル配信する。ホーム画面は静的 HTML/CSS/JS のみで動き、既存の `/api/*` エンドポイントも外部サービスも呼び出さない。バックエンドの既存研究・検証インターフェースは変更しない。

入力はメモリー内のみ。localStorage、Cookie、サーバー保存は使わない。再読み込みで消えることをヘルプに明記する。実参加者の情報は入力しない。サンプルは合成条件であり、現在の旅行事実や価格の根拠ではない。

保存形式は `llm-travel-local-brief` version `1.0`。`synthetic: true`、`state: awaiting_research`、`verification_status: unverified` と9条件を含む。既存の検証済み旅程や ResearchRequest 契約の代用ではなく、人が調査へ引き継ぐための独立した下書き。保存操作はAI起動、情報収集、研究証拠の検証、ルール承認を行わない。

## 検証

既存の unit tests / eval を維持。ブラウザーで初期画面、サンプル、必須・数値・空白入力、確認、編集、JSON ダウンロード、クリア、HTML風テキストの無害な表示、PC/モバイルを検証する。ネットワーク記録でホーム画面が API を呼ばないことを確認する。

Claude の研究解釈・高リスクレビュー担当は維持する。このUI変更はClaudeレビュー実施を意味しない。
