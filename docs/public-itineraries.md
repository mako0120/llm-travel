# 公開旅行プランと改善比較

## UI

`/public.html` は誰でも読める公開ビューである。最初は公開済みプランの一覧を表示し、`?plan=trip-...` で詳細を開く。詳細は、時間別の行動予定、食事・宿泊・費用、根拠確認時点の注意、改善前/改善後を並べて表示する。公開されていない旅程、研究メモ、個人プロフィール、未確認の候補は返さない。

公開 URL は `POST /api/itineraries/{itinerary_id}/publish` を明示的に呼んだ場合だけ作られる。出力の `public_url` を共有に使う。現時点の HTTP サーバーはローカルホストだけを待ち受ける研究用実装であり、インターネットへ自動配備しない。

## 保存と比較

旅程は `itinerary_proposals` に JSON と作成日時を不変で保存する。改善版は `before_itinerary_id` と必須の `improvement_summary` を指定して保存し、`itinerary_improvements` が改善前後の関係を記録する。公開記録は `published_itineraries` に slug、旅程ID、タイトル、公開日時を保存する。

この構成では、公開後に内容を上書きせず、新しい改善版を新規保存して再公開する。公開された比較は「どの行程を何の理由で変更したか」を追跡できる。

## 改善システム

改善は二段階で扱う。

1. 旅行プラン単位では、レビュー済みの新しい旅程を保存し、改善前IDと説明を残して比較する。
2. 再利用ルール単位では、自由記述のフィードバックだけを根拠に pending ルールを提案し、人間が明示承認した条件付きルールだけを次の検索に使う。評価点だけではルールを作成・承認・順位付けしない。

公開された旅程の見た目の比較と、次の旅程に適用可能な改善ルールを分離することで、単発の好みを一般化しない。

## 共有マップと旅行者評価

旅程は任意の `map_points` に、根拠ID付きの緯度・経度を保存できる。公開画面は外部地図タイルに依存しない概略マップとして、訪問順の地点を表示する。商用の詳細地図は、自己ホストまたは契約済み地図タイル・経路サービスを設定してから追加する。

公開プランには1〜5の旅行者評価と任意感想を受け付ける。投稿はまず `pending` として保存し、確認済み評価だけを平均と件数で表示する。評価は旅行前の参考情報であり、改善ルールの自動採用・承認・順位付けには使わない。
