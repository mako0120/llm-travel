# 個別最適化された旅行計画

Issue: #52。旅行計画は保存済みの候補一覧だけで決めず、入力条件ごとに新しい調査パケットを作り、ChatGPT/Codexの候補案とClaudeの独立レビューを分ける。

## 情報源の優先順位

1. 事業者・施設の公式情報と、その事業者が公開するGTFS / GTFS-Realtime。
2. キー不要の公開情報源。Nominatimは目的地の単発座標照会、Wikimediaは文脈・発見候補、Open-Meteoは座標が得られた目的地の7日間の時間別予報候補にだけ用いる。
3. Google Maps Platformは無料利用枠内でも請求設定と制限済みキーが必要な補助接続。検索・経路取得は最小フィールド、使用上限と予算アラートを設定する。
4. TikTokは承認済み公式製品の発見候補だけに使う。食べログは許可済み公式・ライセンス接続がある場合だけに使う。

`POST /api/free-research` は、明示された目的地に対してNominatim、Wikimedia、座標取得後のOpen-Meteoを順に照会する。全結果は `unverified` で返し、保存済み候補のランキングや旅程の事実には自動採用しない。

## 商用モード

`LLM_TRAVEL_DEPLOYMENT_MODE=commercial` では共有の無料 API を呼び出さず、`commercial_provider_configuration_required` を返す。商用提供を始める前に、Nominatimは自己ホストまたは商用プロバイダー、Open-Meteoは商用サブスクリプション、Wikimediaは再利用する各コンテンツのライセンス・帰属とレートの確認、GTFSは各事業者のライセンス確認を完了させる。

この切替は「無料 API の商用利用を許可する」という主張ではない。契約や自己ホストの接続設定が未実装・未確認の間は、利用者への外部照会を停止する安全弁である。

未許可スクレイピング、検索結果だけからの営業時間・運賃・時刻表・予約可否の断定、現在情報の創作は行わない。Nominatimは利用者が確定して送信した目的地に対し、1秒に1件以下の単発検索と帰属を必須にする。公開データは無制限のAPIではない。

## ChatGPT/Codex と Claude の対話

`scripts/run_dual_agent_review.py input.json output.json` は、オペレーターが明示的に起動するローカル手順である。Webアプリから自動実行しない。

```json
{
  "requirements": {
    "destination": "京都",
    "nights": "2",
    "budget": "50000",
    "themes": "街歩き・グルメ",
    "transport": "公共交通機関"
  },
  "evidence": []
}
```

1. ChatGPT/Codexのターンは、研究パケットから候補案を出す。根拠が不足すれば `needs_research` を返す。
2. Claudeのターンは同じパケットと候補案を読み、`approved` または `needs_revision`、不支持の主張、必要根拠、代案をJSONで返す。
3. 両方の実行時刻・原文・根拠を出力ファイルに残す。実行されなかったClaudeレビューを表示・保存しない。
4. `approved` でも、既存の旅程保存では全表示項目が有効な根拠に結びつき、別々のClaude/Codexレビューが必要である。

CLI認証はそれぞれのローカル利用者セッションに留める。APIキー、GitHub書き込み権限、デプロイ資格情報は、スクリプトの入出力・ログ・旅行アプリに渡さない。

## 旅程の完成条件

詳細な行動予定は時間単位で、各行に王道/穴場、移動手段、所要時間、費用、根拠を表示する。公共交通は対象日の公式GTFS/公式時刻表から路線名・駅名・出発時刻を得られたときだけ表示する。タクシー・レンタカーは公式または許可済み経路ソースで得た時間を使う。

食事候補は複数、地元の名物・隠れた店の候補、宿泊候補は利便性・快適さ・予算を根拠付きで比較する。移動費・宿泊費・食費・入場料と合計は、各金額が根拠に結びつくときだけ出す。根拠が不足すれば未確認または追加調査として表示し、数字を補わない。
